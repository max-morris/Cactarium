HTTP API

CactUp talks to the Cactarium through a small JSON API. Its base URL is {{ doc.base_url }}/api/v1. Reads need no token and see public entries and published versions only: a pending or hidden entry answers 404, like a missing one. Writes need an API token.

The response bodies are the Rust types in api.rs of the shared crate cactup-ecosystem-common, which the server and CactUp both compile against; a stack release is FrozenStack in its stack.rs. Field names are kebab-case.

Response headers

HeaderMeaning
api-generationOn every response under /api/v1; currently 1. A client that sees a generation it doesn't know should ask its user to upgrade rather than guess.
x-cactarium-unpinnedtrue on every @head or @master response: the body is not a release and its repos are not all pinned.
x-cactarium-untrustedOn every @head or @master response: true when the entry isn't trusted (neither it nor its owner), whose branch tips nobody reviewed, else false. Releases don't carry it.
x-cactarium-contactOn every stack release response, @head and @master included: where to go for help with the stack, its declared contact, else its repo. Empty when it has neither.
x-sha256On a sim download: the file's sha256, in hex.

Errors and limits

An error is a non-2xx status with a body like

{"error": {"code": "not-found", "message": "Not found"}}

The code is one of not-found, unauthorized, forbidden, bad-request, conflict, rate-limited or internal, and the message is meant to be shown to the user as it is. Some endpoints are rate-limited per client address, per minute; past the limit they answer 429 with rate-limited.

Read endpoints

GET /resolve?req=owner/name@range

The best version of a package, stack or sim matching a reference: the highest published, non-yanked, valid version in the range, on the track the range names. An exact request such as @=1.2.3 also reaches a yanked version, which the response marks "yanked": true. For a package, @head and @master resolve to its default branch's tip, with the unpinned headers; for a stack they are refused (fetch releases/head instead).

Response: Resolved. slug is the exact reference chosen, kind is package, stack or sim, url is the repo to fetch from (for an entry registered from a repo), contact is the version's declared contact or the repo, and the fields of VersionInfo follow inline.

curl -G {{ doc.base_url }}/api/v1/resolve --data-urlencode 'req=max-morris/carpetx@mixed-precision:^1'
{
  "slug": "max-morris/carpetx@mixed-precision:1.4.0",
  "kind": "package",
  "url": "https://github.com/max-morris/CarpetX.git",
  "contact": "https://github.com/max-morris/CarpetX/issues",
  "version": "mixed-precision:1.4.0",
  "track": "mixed-precision",
  "tag": "mixed-precision/v1.4.0",
  "commit": "3f2c9e1a00112233445566778899aabbccddeeff",
  "tree": "…",
  "yanked": false,
  "yank-reason": null,
  "state": "ok",
  "curated": false,
  "published": 1762300800
}

state is ok, invalid, tag-moved (the tag points elsewhere upstream now; the frozen commit still counts) or upstream-missing. published is in Unix seconds. tag is null for versions named by commit and for uploads.

GET /entries/{owner}/{name}

Any entry. Response: EntryInfo: its slug, kind, summary, whether it is verified or curated, its repo and contact, its number of saves (hearts), its tracks (the default track as "") and the labels of its published versions.

GET /packages/{owner}/{name}/versions

Every published version of a package, newest first within each track, yanked and invalid ones included and marked. Response: PackageVersions, whose versions are PackageVersions: the VersionInfo fields, the repo url, the thorns (ThornInfo: arrangement, thorn, the repo-path to write in a thornlist, and the CCL facts) and the claims (ClaimInfo: kind, target, range, note).

GET /packages/{owner}/{name}/versions/{head|master}

The package at its default branch's tip, read now, in the shape of one PackageVersion whose version is head or master (the two mean the same for a package). Carries x-cactarium-unpinned and x-cactarium-untrusted. For an untrusted package it answers 403 unless the site allows untrusted branch tips. Limited to 12 requests a minute.

GET /stacks/{owner}/{name}/releases

A stack's published releases. Response: StackReleases: the slug and a list of VersionInfo.

GET /stacks/{owner}/{name}/releases/{version}

One release, by its exact version: 1.2.0, or track:1.2.0. A yanked release is still served. Response: FrozenStack: format, the exact stack reference, root, the thornlist (filename and verbatim text), one repo entry per repo with its pin, and the recipe (the definition) it was cut from. Carries x-cactarium-contact.

With head or master in place of the version, the response is the stack's unpinned form, resolved now: repos left on a branch tip have no commit, and stack ends in @head or @master. It carries x-cactarium-unpinned and x-cactarium-untrusted, answers 403 for an untrusted stack unless the site allows untrusted branch tips, and is limited to 12 requests a minute.

GET /sims/{owner}/{name}/{version}/download

One sim version's .sim file, by its exact version, such as 1.0.0; a yanked version is still served. The body is the stored file (content type application/toml), with its sha256 in x-sha256.

API tokens

Write endpoints take a token in the Authorization header:

Authorization: Bearer cactarium_…

Create tokens on your Settings page, under API tokens: give each a name and a lifetime from 1 to 366 days. A token is shown once, when it is created, and stored only as a hash; revoke it there at any time. Every token has the scope publish: it publishes sims and stack releases, and refreshes repos, as its user, under the user's own name and the organizations the user belongs to. The site's operator can also create one with just cli token <username> (90 days unless --days says otherwise).

A missing, expired or revoked token, or one whose user is banned, gets 401.

Token endpoints

All three answer with what was created or found. Published holds the new version's exact slug, the url of its page on the site, its visibility (public, or pending while the entry or the release waits for review), and warnings a reviewer will look at.

POST /sims/{owner}/{name}

Publishes the request body, a .sim file, as a version of owner/name, creating the sim if it is new. The optional query parameter version=X.Y.Z names the version; without it the upload becomes the next major version. The file must pass the checks; the warnings come back in warnings. Answers 409 if the version exists or owner/name is not a sim, 403 for a namespace you can't publish under, and 400 for a repo-backed sim or a file that fails a check. Limited to 20 requests a minute. Response: Published.

curl -X POST -H "Authorization: Bearer $TOKEN" --data-binary @bhns.sim \
  '{{ doc.base_url }}/api/v1/sims/max-morris/bhns-gw230529-dense?version=1.0.1'

POST /stacks/{owner}/{name}/releases

Cuts a release of an uploaded stack, creating the stack if it is new. The body is a JSON ReleaseRequest: the definition (the cactarium-stack.toml text, whose [stack] name must be {name}), the stack's own thornlist or null, and the version, 1.2.0 or track:1.2.0. Refused for a repo-backed stack or a version that exists. Limited to 10 requests a minute. Response: Published.

{
  "definition": "format = 1\n\n[stack]\nname = \"carpetx-mp\"\nextends = [\"et/carpetx-stack@1.0.0\"]\n",
  "thornlist": null,
  "version": "1.0.0"
}

POST /packages/{owner}/{name}/refresh

Checks the entry's repo for new, moved and deleted tags now, like Check for new tags now on the site. The token's user must manage the entry. Despite the path, it works for any entry registered from a repo. Limited to 10 requests a minute. Response: Refreshed: the slug, how many versions this check added (new-versions), and how many of the entry's versions wait for review (awaiting-review).

Outside the API

The site's own downloads, /{owner}/{name}/{version}/download.sim for a sim and /{owner}/{name}/{version}/download.th for a stack's frozen thornlist, serve plain files. Forge webhooks go to /hooks/{github|gitlab|bitbucket}/{entry-id}; see Publishing.
