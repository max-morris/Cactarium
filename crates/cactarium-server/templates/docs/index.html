Cactarium

Cactarium is a registry for the Cactus and Einstein Toolkit community. It holds three kinds of entry, each named owner/name, where the owner is a user or an organization:

  • Packages: a git repo of thorns, versioned by its tags. The code stays in its repo. For each version Cactarium records the commit named by the tag when it first saw it, the thorns found there, and what their CCL files declare.
  • Stacks: versioned thornlists. A stack can be a plain thornlist, a recipe built on other stacks, or both. Every release pins every repo to a commit and never changes afterward.
  • Sims: a parfile together with the exact configuration that it ran on, as one .sim file: the thornlist, a pin for every repo, and the inputs that the parfile needs from outside the source tree.

Thorns have pages of their own: /thorns/CarpetX/Loop lists the packages that provide the thorn and the stacks and sims that build it. See Finding things.

Accounts

Reading needs no account. Every public page, every download and the whole read API are open to anyone.

To publish, sign in with GitHub or ORCID. The first time, you choose your Cactarium name: the namespace under which everything that you publish lives, as in yourname/package. Names use lowercase letters, digits, ., _ and -, start with a letter or a digit, and are at most 64 characters long. Users and organizations share one namespace, and a few names, such as docs, api and cactarium, are reserved.

Your Settings page lets you link the other sign-in method, so either one reaches the same account. It also holds your API tokens, which let Cactup publish on your behalf (see the API).

How Cactup uses it

Cactup is Cactarium's client. When you add a package, Cactup sends the reference that you typed, such as max-morris/carpetx@mixed-precision:^1, to Cactarium, which picks the version and returns its frozen commit; Cactup then fetches exactly that commit. Cactup also installs stack releases, imports sims, and publishes sims and stack releases with your API token.

The commands and the .sim format are documented with Cactup, not here: see Cactup's docs on its commands and Cactup's docs on the .sim format. These pages cover what is specific to Cactarium: the manifests that you commit, how versions are frozen and reviewed, and the HTTP API.
