Files that a sim pins by sha256 (a tarball component, an input's download), submitted with cactup download submit <url>. Cactarium fetches each once in the background and checks its sha256; it keeps no copy. Only a verified download can be decided. A sim pinning a download that isn't approved isn't published: an upload is refused, a tag waits, and a tag pinning a rejected download becomes an invalid version. Trusted users' and admins' submissions are approved once verified.

Approve without fetching

For a download too big for the server to fetch, or on a host it can't reach: approved as you vouch for it, without the server checking its sha256 (the audit log says so). Also approves one awaiting review, whose fetch failed, or that was rejected. The same as just cli download approve <admin> <url> <sha256> [--note …].

A rejected download can be reopened (back to pending) or approved. Sim tags that became invalid over it stay invalid until read again: just cli reread <admin> <owner/name> <version> (or Admin, Entries, Re-read invalid version).
